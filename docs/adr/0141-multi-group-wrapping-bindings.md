# ADR 0141: Multi-group wrapping weight-source authoring

- Status: Proposed
- Scope: Batch document command, captured component selection, and multi-group inspector

## Decision

Extend `ComponentWrappingEdit` with `.binding(ComponentWrapBindingChoice)` and reuse the existing captured `ComponentWrappingSelectionTarget` state/session/Store path. Read the hierarchy once, construct one `ComponentWrapBindingPlan` from the complete selected owner set, validate its common candidate before staging any field updates, then mutate and serialize one DOM. No owner can bind to another selected owner or any selected owner's descendant. Ancestors remain eligible, and binding edges do not introduce a separate recursion/SCC policy.

Qt builds the union exclusion at `component_property_widget.cc:778–798`, applies the chosen reference to all selected components at `801–805`, and adds one group operation. Its field setter (`document.cc:782–811`) does not require active Skin or Cloth. Native batch binding therefore also stores references on None and unknown wrapping modes without normalizing mode, other wrapping fields, unknown metadata, or assets. As in ADR0137, native authoring offers supported unlinked groups only; imported unknown-link references remain lossless rather than being newly authored.

Own Children removes a nonempty override. Absent and stored empty values remain distinct domain values, but the UI presents their common effective Own Children choice. Such a choice on an already equivalent source is a byte-preserving no-op, including mixed absent/empty selections. Exact nonempty UTF-8 references remain distinct. A current retained or missing target is described without implying it is inactive in the core. Mixed real references never become an implicit replacement.

The multi-group inspector has a Weights From menu and readable current-source descriptions for each selected owner. Named owners and targets include their exact IDs in accessible values; unnamed IDs speak once. The menu is built from the current snapshot only while its captured target is current. Busy, stopped, document replacement, selection/constraint away-and-back, and stale source contexts retain existing rejection rules. Changes use one history entry and refresh both geometry/source and material inputs; all-no-op batches retain redo and input identities.

## Verification and limits

Pure tests cover common union exclusions, ancestors, active/None/unknown modes, exact raw and mixed values, partial/all no-ops, field locality, history, cancellation, stale actors/windows, Store routing, assets, and accessible descriptions. Hosted rendering uses explicit stubs for every native preview and material boundary.

Native acceptance is separately source-audited before execution. The proposed bounded family extends the collision-free body/guide fixture with one ordinary guide chain and a second Uncombined Cloth group. A test-only production48b C++ observer checks each garment's cache independently: every donor must exist in the actual generated snapshot and belong to that garment's own guide before binding or to BODY after binding, including legitimate interpolated BODY nodes. The existing first-garment nonempty bound-fold requirement remains; the second garment's fold count is reported without inventing a guarantee.

Public Swift hints are an aggregate original-identity catalog and do not establish complete per-garment ownership. A separately guarded real Store test must apply the actual batch action, retain unresolved hint entries honestly, require valid nonflat baked normal response, match an independent fresh reopen, and Undo once. All native delegates admit exact reviewed archive hashes before entry. The reviewed production48b observer passed all four exact cases: bound garment 1032 has 247 BODY influences including 139 interpolated-node influences and 10,383 fold bytes; garment 1033 independently has 205 BODY influences including 117 interpolated-node influences and 0 fold bytes. Own Children, returned Own Children and the empty target retain all 137 GUIDE2 and 117 GUIDE3 influences respectively. The separately reviewed real Store test passed once: 65,536 opaque normal texels, 1,293 nonflat texels and 181 distinct valid directions, exact independent fresh normal equality, one Undo and assets preserved. Public Swift hints remain aggregate evidence; the observer supplies the complete per-garment donor proof. Final composition/release gates remain pending. Physical pointer and VoiceOver acceptance is separate from hosted rendering. No new core API, core adoption, dependency/pin change, unknown/cyclic native probe, GPU test, or parameter sweep is included.

Focused verification: 18 pure/stub/hosted authoring tests pass after the error-help/accessibility branch adopted the existing actionable `EditorStore.message` mapping. The reviewed native test did not need rerunning for that message-only change.

Presentation precomputes an exact UTF-8 candidate dictionary and component-identity set once, then uses indexed lookups for each owner reference. This removes repeated owner-count × hierarchy-count scans without changing candidate or source display order. Data keys preserve byte distinctions instead of Swift String canonical equivalence. Functional lookup tests cover an actual NFD target versus an unresolved NFC reference, duplicate-identity rejection, duplicate display names, and 256 owners with 32 targets. Those six presentation tests passed as a behavior baseline before the indexing refactor and pass afterward; this is not a fabricated performance RED or a timing benchmark. The final 18-test pure/stub scope and full Swift lint pass; no native rerun was needed for indexing and error-language changes.
