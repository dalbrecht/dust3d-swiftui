# ADR 0011: Lossless selected-node clipboard

Status: Accepted for the document foundation of issue #22. Foundation and native integration are separate reviewed stages; no clipboard UI completion is claimed here.

Selected-node copying produces an immutable fragment archive, selected node IDs and an ordered list of semantic identities. Include only selected nodes and internal selected edges, their parts, matching component references and ancestor groups. Close known `cutFace` profile dependencies transitively by including complete referenced parts/graphs. Dependency nodes are not part of the user's pasted selection. Preserve opaque metadata attached to retained graph objects and groups, extension namespaces and all binary assets, because unknown extension fields may reference assets. Do not copy unrelated source canvas objects/animations/settings into the destination.

Paste requires a fresh, globally unique identity for every semantic node/edge/part/component identity. Remap known IDs/references only; never replace arbitrary unknown text. Identity injection and placement offsets are explicit inputs, keeping randomness and system pasteboard access outside the document layer. Pasted parts retain their source settings. Preserve destination hierarchy, root/container settings and assets; append copied component roots. Retain profile dependencies and reject resulting known profile cycles.

Merge assets by exact archive name/type/content and metadata. Identical entries can be shared; conflicting entries reject atomically rather than renaming opaque references incorrectly. Source and destination archive limits apply before publication. Copying includes all assets by design, which must be disclosed in native integration documentation. Unrelated source model objects are excluded.

Partial selections may leave disconnected groups in a copied part. The actor integration must normalize those new parts with explicit split identities in the same undo transaction before engine generation. Document commands remain low-level building blocks. Native Cut must write the clipboard successfully before deleting editable nodes, preserve read-only selection, and use existing one-step removal normalization. Standard text-field editing must retain Cut/Copy/Paste through the responder chain.

Acceptance: ordered identity remapping, partial selections, transitive profiles, nested/repeated component references, child geometry pruning, unknown data/namespaces, assets including conflicts, malformed fragments, stale/colliding IDs, numeric/count/size limits, exact one-step undo/redo, session normalization and native cross-window paste/save/reopen. Qt text clipboard interoperability requires its own adapter/fixtures; the binary lossless fragment format must not pretend to be Qt snapshot XML.

When source and destination canvases use different default namespaces, native graph elements adopt the destination canvas namespace so existing readers and commands can find them. Opaque children/attributes retain their original namespace bindings, including inherited prefixes and explicit empty-default resets. Materialize inherited bindings before detaching XML subtrees or comparing asset metadata; equal prefix text with different namespace URIs is not identical metadata.

Classify `cutFace` through inherited `dust3d::Uuid` semantics before looking up parts. Presets remain values even when an unrelated part has the same text as its ID. UUID-shape classification is case-preserving. The snapshot generator then resolves parts by exact original spelling (`parts.find(cutFaceString)`); brace mismatches are not links and must remain dormant. Conservative ID collision checks separately reject brace aliases. Known profile-target replacements must remain UUID-shaped. The same classifier is used by joining and profile-cycle validation. Reject duplicate destination component containers before collision discovery.
