# ADR 0010: Cross-part endpoint joining

Status: Accepted for issue #20. Implemented and locally verified; see [verification](../part-joining-verification.md).

The splitting stage makes disconnected pieces independently previewable, but the Connect menu still limits targets to the same part. Add an explicit join command for connecting editable chain endpoints across parts and reconnecting split pieces. Keep raw addEdge as a low-level building block; app connections and node extension use the higher-level command so endpoint and orientation rules are consistent.

Source oracle: `Document::isNodeConnectable` (<2 incident edges), `addEdge`, `createNode`, `updateLinkedPart` and serialization in `application/sources/document.cc`. For an existing source endpoint whose incident edge starts at that node, the new edge points target → source; otherwise it points source → target. When parts differ, walk the whole target chain from the target endpoint, reorient its edges to join consistently, and move its nodes/edges to the source part. Source geometry/part settings win. Require a fully connected resulting chain or valid loop and reject unsupported branches/partial disconnected target consumption atomically.

Joining intentionally consumes the target part and its leaf component settings; this is the upstream operation's settings replacement, not an unrelated metadata change. Retain all node/edge IDs and their unknown fields, unrelated XML/hierarchy and archive assets. Exact snapshot undo restores the consumed target settings and topology. Disclose the source-settings rule in the UI/help and verification documentation.

For target component references with actual child components, preserve child geometry and hierarchy by retiring the part link while keeping the component as a group. Leaf target references may be removed with the consumed part. Keep unknown metadata on surviving elements and avoid touching component-like extension tags outside the actual components tree. Cover repeated/nested references and namespaces. Do not delete unrelated descendant geometry while consuming a part.

Known linked-profile references serialize as the `cutFace` attribute on parts and nodes (the internal Qt member is named cutFaceLinkedId). Redirect references equal to the consumed part ID to the source part. Do not rewrite arbitrary text or unknown fields containing the same string. Preserve unrelated references and assets. Reject any resulting known part/node profile cycle with a typed error before publishing the document or invoking the engine.

Keep join mutation in the document library, orchestration/UUID allocation in the session/app boundary, and menu availability in pure snapshot-derived state. Endpoint availability must check both read-only state and degree. Empty selection can create a fresh part; a single editable endpoint can extend a chain. Multiple selection or an interior/read-only node should not offer a misleading extension action. New Part remains available independently. X/Y/Z locks do not block topology operations.

Acceptance: source/target orientation combinations, same-part loop closure, split→join returning to one generated part, unassigned/missing/duplicate/self/readonly/interior/branching inputs, part style replacement, cutFace links, unknown node/edge and unrelated metadata/assets, nested target references, namespace handling, failed-batch atomicity and exact one-step undo/redo. Exercise the real actor-to-pinned-engine path and native connect/extension/save/reopen. Keep clipboard, broader component editing and full parity explicitly pending.
