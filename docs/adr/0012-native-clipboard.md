# ADR 0012: Native clipboard transport and transactions

Status: Accepted for issue #22. Native integration builds on the reviewed document foundation from PR #23.

Use a private pasteboard type `org.dust3d.node-clipboard.v1` with a bounded binary transport: magic, four-byte big-endian JSON length, versioned metadata and raw `.ds3` bytes. This avoids base64 expansion of assets. Version 1 metadata records a caller-supplied Copy/Cut token and sorted explicit selection. Cap metadata at 2 MiB, archives at 256 MiB, tokens at 128 UTF-8 bytes and selection at 10,000 IDs. Validate version, uniqueness, lengths, selection, archive and graph before publication; rebase sliced Data before indexing. Unknown transport versions reject with a typed error.

The platform boundary owns NSPasteboard and fresh Copy/Cut tokens. EditorSession serializes/decodes off the UI actor, generates fresh graph/split UUIDs, applies placement, normalizes new groups and selects only explicit copied nodes. Dependency-only profile nodes are retained without selection. Copy is read-only. Copy/Cut register a lazy NSPasteboardItemDataProvider holding an immutable Data snapshot; they publish only its type promise, without passing the archive to synchronous setData/writeObjects calls. AppKit retains the provider independently of the source document window and requests bytes when a consumer needs them. Cut requires successful promise registration before existing session deletion; only editable selected nodes are copied/removed, and readonly nodes stay selected. Registration failure leaves the document untouched. The clipboard includes all embedded assets to preserve opaque references; disclose that in help and documentation.

Add explicit construction partitions to the document paste command. Discover split requirements on the fragment before allocating identities, including readonly copies. Partition keys must be newly pasted parts, fresh identities must remain globally distinct (including conservative UUID-alias checks), and normal size/count/metadata limits apply. An internal readonly construction allowance is reachable only after fresh pasted-part validation; existing readonly parts retain ordinary command protection. This preserves readonly style while making disconnected copies previewable in one transaction.

Initial paste into a document containing source node IDs moves by 0.04 on Y/Z; external paste starts in its original coordinates. Successive pastes of the same token advance another 0.04. This intentionally spaces repeated copies; it is not a claim of exact Qt placement parity. Bookkeeping is transient, advances only on success and resets on Open. Undo/redo restores committed bytes/IDs without restoring transient selection or placement.

Use focused SwiftUI commands and a small AppKit boundary for pasteboard access, native text responder routing and selection-based menu enablement. Observe text-selection notifications so Cut/Copy become enabled immediately; preserve Select All when replacing the pasteboard command group. Command-A routes to field text or node selection by current responder; native text Cut/Copy/Paste remain text actions. The inspector also exposes explicitly named node clipboard actions. The system `PasteButton` and Core Transferable load the custom representation asynchronously and manage type availability. The editor exports that type in its Info.plist. Field paste continues through the native text responder; raw `NSPasteboard.data(forType:)` reads are excluded from the main-actor store.

Native binary interchange, actor normalization, focus routing and save/reopen are this stage's acceptance criteria. Qt snapshot-text clipboard interchange, arbitrary branching, empty-part cleanup and full editor parity remain separate work. Thin AppKit/GPU behavior has manual evidence rather than claimed unit coverage.

Packaging accepts `DUST3D_APP_OUTPUT_DIR` for isolated validation bundles while reusing the existing build cache, so metadata/signature checks can run without replacing a running app bundle. The default output location is unchanged. The native clipboard type conforms to public.data and has no file-extension association.
