# ADR 0009: Disconnected part splitting

Status: Accepted for the editor prototype, issue #18. This stage does not complete the full editor port.

Deleting nodes or disconnecting an edge can leave disconnected chains inside one part. The pinned generator expects a connected chain, so the editor must split affected parts into connected groups in the same undo transaction. Preserve all unrelated parts and unsupported archive data. Part merging, branching-chain handling and empty-part cleanup remain subsequent parity work.

The Qt source oracle is `Document::removeEdge`, `removeNode`, `splitPartByEdge`, `splitPartByNode` and `updateLinkedPart` in `application/sources/document.cc`. It creates parts/components for connected groups and redirects linked-profile references to the largest group. Native splitting should preserve the original part/component identities for the largest group (tie: document node order), clone metadata for the other groups, and leave references to the original identity pointing at the largest group. This differs from Qt's fresh-ID implementation while preserving its relevant geometry/reference behavior and improving unknown-reference stability.

Keep UUID generation in `EditorSession`, outside pure state and archive commands. Add typed split requirements and identity values, plus an explicit document split command. Requirements report the affected part ID, additional group count, and component references per new group. The command recomputes/validates current connected groups and requires exactly enough fresh identities; reject duplicates, collisions, wrong counts, read-only parts and size/component limits atomically. Do not add randomness or implicit identifier allocation to `EditorState`.

Compute connectivity deterministically using node/edge indexes and adjacency lists, bounded by the existing graph limits. Only normalize parts affected by the current graph deletion, rather than opportunistically rewriting other disconnected or unsupported content. Edges connecting different parts remain incompatible with the native engine; do not silently reinterpret them as connected groups.

Expose a document requirement query for a set of affected part IDs. The actor preflights a removal batch on a private document value, determines affected parts before each removal, queries requirements after the batch, allocates identities, then appends split commands to the original batch. Publish through the existing `EditorState.apply` transaction so removal plus all splits make exactly one undo step. Preflight failures must leave the session unchanged. Use this path for actor `apply` graph removals and `deleteSelection`; pure low-level archive commands remain explicitly composed building blocks. Skip preflight for batches without graph removal.

For each additional group, copy the original part element and change only its identity; reassign member node/edge part references. Copy every component reference to that original part, with fresh component IDs and updated `linkData`, preserving style, unknown attributes and non-component child XML. Insert copies adjacent to their originals in deterministic order. A copied component must exclude actual component children so splitting does not duplicate existing child geometry or component IDs; retain those children on the original component. Cover nested and repeated references explicitly. Parts with no component references should not acquire new rendering links implicitly.

Preserve archive assets byte-for-byte. Retain the original unknown part/component data and clone it rather than rebuilding known fields. Preserve existing node/edge IDs and ordering. This does not promise interpretation or semantic remapping of future unknown schemas. Known linked-profile references keep the original ID for the largest group. Keep empty part/component metadata in this stage; later cleanup must make deletion scope explicit and preserve unrelated content.

Before generating identities or cloning result subtrees, bound new part/component counts and model size. Requirement discovery must reject an excessive component-copy product before allocating UUID arrays. Validate all injected identifiers against existing IDs and each other; bound each new identifier to 128 UTF-8 bytes (the session emits standard brace-wrapped UUIDs). The metadata-copy estimate is conservative and may reject edits near the 16 MiB model limit; final archive validation still enforces the actual size. Re-parse/validate the final archive before publication.

The engine integration test target now also depends on the existing local editor-model target. This introduces no external package; it proves actor preparation and engine generation together, which low-level archive tests alone cannot establish.

Acceptance: disconnect a Capsule edge and delete its middle node through the actor; generate the resulting split model with the pinned engine; verify grouping, copied style/metadata, nested hierarchy order, multiple component references, linked profiles, assets, selection, all size/identity/readonly failures, one-step exact undo/redo, and native open/save. Do not claim M2 or full Qt parity solely from these cases.
