# Node clipboard document foundation verification

`make ci` passes 128 tests, formatting, both app builds, coverage gates and Qt-free checks. Document line coverage is 1451/1518 (95.59%); editor model 576/582 (98.97%); pure editor state 325/325 and undo domain 92/92 (100%). The pinned engine revision, C++ sources and C++ standards are unchanged. These figures do not certify inherited C++ or native UI/GPU coverage.

Tests copy partial and complete selections, retain only internal selected edges and preserve source ordering. Profiles are closed transitively, including a part initially copied partially then reached as a full profile dependency. Selected IDs exclude dependency-only nodes. Nested/repeated component references and necessary ancestor groups survive, while unrelated child geometry is pruned; references to excluded parts become groups if retained children need them. Unknown fields/children on retained objects, default namespaces and binary assets survive. Unrelated source canvas objects/animations are not inserted into the destination.

Paste tests cover explicit fresh identity mapping, node/edge/part/component references, part settings, nonzero placement offsets, named cut-face presets that happen to match unrelated identities, unchanged opaque text, missing destination containers, destination root metadata, empty assets, identical asset sharing and conflicting bytes/type/metadata. Conflicting entries throw a typed error without changing history or archive bytes. Asset comparisons preserve header metadata and intentionally reject incompatible same-name entries instead of guessing how unknown references should be rewritten.

Negative tests cover empty/missing/unassigned selection, missing/extra/duplicate/colliding/overlong fresh IDs, invalid/nonfinite/out-of-range offsets, derived geometry overflow, duplicate/missing imported semantic identities, invalid component references, self/cross-part/mismatched-part edges, branching topology, duplicate component containers and profile cycles. Count tests exercise the 10,000-node/part/component destination limits. Existing archive, XML-depth, model-size and history gates remain active; this stage does not claim allocation-failure stress certification at the 256 MiB archive limit.

DocumentHistory tests prove one-step exact undo/redo. Pinned-engine tests paste full and two-node Capsule copies into blank archives with fresh UUIDs, generate valid meshes, and retain the full Capsule's triangle count. A disconnected selection intentionally remains a low-level fragment: tests discover its new part's split requirement, and the next actor integration must compose normalization before generation.

This PR provides the document value/command foundation only. It does not expose native Cut/Copy/Paste, write the system clipboard, define clipboard wire serialization, implement automatic identity allocation or finish the clipboard acceptance milestone. Native focus routing, cross-window paste, normalized actor transactions and save/reopen evidence belong to the next reviewed stage of #22. No new native UI/GPU comparison is claimed for these library changes. Qt snapshot-text clipboard interoperability remains a separate adapter task.

All source assets are included because unknown fields can reference them; callers must disclose this when exporting clipboard data. Unknown schema-specific identity references remain opaque. Same-name asset conflicts require explicit resolution instead of silent remapping. These constraints are deliberate and do not constitute full editor parity.
