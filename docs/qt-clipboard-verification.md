# Qt clipboard verification

Full `make ci` passes 264 XCTest tests, formatting, builds, coverage and Qt-free linkage. Swift line coverage: mesh 66/67; document 1909/1986; editor model 1067/1073; pure editor state 453/453 and undo 97/97. Inherited C++ coverage is not measured. Eight focused XCTest cases pass. TDD first failed on the missing snapshot initializer, text-payload initializer, session text-paste/dual-copy APIs and dual-representation provider. Tests then verify:

- Exact canvas XML bytes and unknown extensions survive archive wrapping and reopen, including rebased Data slices.
- Malformed/wrong-root XML, duplicate containers, entity declarations, excessive depth and >16 MiB data reject; existing document validation handles finite bounded geometry.
- Empty snapshots and missing parts cannot become clipboard fragments; invalid tokens reject.
- Text imports select all included nodes. Repeated successful text pastes advance placement, failure preserves redo/bookkeeping, Open resets placement and Undo restores exact original bytes.
- Native Copy retains reference-image asset bytes while text remains asset-free. Native transport selection and the text XML refer to the same immutable fragment.
- The AppKit provider serves distinct native and text bytes, ignoring unadvertised types. Controller text Paste publishes one document change and preview; unrelated text causes a typed error without modifying document/history or notifying a write.
- Capsule XML text generates nonempty pinned-core geometry; text exported from the resulting native selection generates the same triangle count and exact undo/redo remains available.

Source comparison used inherited `application/sources/document.cc` Copy/Paste and `dust3d/base/snapshot_xml.cc` parsing/serialization. This establishes the transport shape, not a completed Qt GUI transfer. The initial native attempt was blocked by a locked Mac. After access returned, QA reused the same app path/bundle identity and disposable fixtures. Pasting plain Qt-shaped XML through the native clipboard added a fresh-ID node and updated the 80-triangle Capsule to 96 triangles. Native Copy/Paste added a second node at the expected 0.04 Y/Z offset; that overlapping geometry failed generation, and the app correctly retained its last valid mesh with a visible error. Two Undo steps restored the original 80-triangle model; Save compared byte-identical to the source.

Coordinate-field Copy/Paste retained text and did not add nodes when focus transitions were observed between input actions. An initial automation batch sent Copy too soon after focus changed and retained the earlier XML clipboard; Paste correctly put that text in the field, and Reset discarded the uncommitted draft. Repeating with separately observed focus/selection copied and pasted 0.8 correctly. This is recorded as an automation timing limitation, not a reproduced app defect.

To prove actual format preference, opened a disposable Capsule archive with a synthetic one-pixel canvas.png asset, copied all three nodes, created an independent blank window and pasted. Three fresh nodes, two edges, an 80-triangle preview and the reference image/opacity controls arrived. Since plain XML contains no asset bytes, this demonstrates preference for the richer native representation. Inspected the rendered mesh/reference canvas. One keyboard Undo removed graph and image together. Actual native↔Qt GUI transfers remain pending; source-format comparison and pinned-core tests do not replace them. No unavailable design baseline was invented. See [ADR 0027](adr/0027-qt-clipboard-text.md).
