# Owned Metal material renderer verification

Issue: Apple #129. The renderer is implemented separately from current app
viewports; this stage does not claim app material adoption or full M4 parity.

## Acceptance evidence

Four upload/order tests and nine actual Metal tests pass locally, together with
the existing indexed-renderer test (14 targeted tests, no failures or skips).
They cover combined payload admission and padded image rows, invalid inputs,
cancellation, independent asymmetric atlas orientation, alpha 0/1/128/255,
opaque depth, transparent source-order independence and camera resorting,
superseded results, original error propagation, neutral maps and individual
metallic/roughness/normal/emission effects, tangent/mapping fallback, and actual
pinned-core baked geometry in solid and wireframe modes. Both offscreen tests and
MTKView presentation use the same production encoder. GPU tests explicitly skip
when Metal is unavailable rather than claiming rendering evidence there.

The SDK compiles under strict Swift 6 concurrency. Fresh buffer/texture owners
transfer from a builder actor with `sending` and noncopyable ownership; no custom
unchecked Sendable or preconcurrency suppression is used. GPU completion tests
await a completion continuation without blocking the main actor.

Optional local evidence is generated by setting `DUST3D_METAL_QA_OUTPUT_DIR`
when running the rendering tests. These images are offscreen production-encoder
output, not app screenshots or portable golden baselines. No local baseline is
committed.

## Full local gate

`make ci` passed with 600 tests and no failures, coverage thresholds, formatting,
native builds, Qt-link checks and isolated app bundle rebuild checks. Measured
line coverage: upload admission 79/79, triangle ordering 65/65, actor resource
builder 113/116, main-actor encoder 96/131. The remaining encoder lines include
native drawable presentation and platform failure paths; offscreen rendering
does not prove live drawable presentation or app integration.

## Limits and remaining acceptance

Color/emission use sRGB textures and an sRGB attachment, with linear shading and
straight-alpha hardware blending. Normal/scalar maps remain linear. The preview
uses GGX direct lighting with a soft ambient term; environment IBL, AO and full
Qt shading equivalence are not established. Samplers currently have no mipmaps.
Mapped triangles conservatively enter the transparent pass if any color-atlas
pixel is transparent; this can disable depth writes for opaque atlas regions.
Centroid sorting cannot exactly resolve intersecting or coplanar transparency.
Logical payload quotas exclude CPU workspace, driver overhead and in-flight
replacement resources and are not hard process-memory caps.

Current app UI remains unchanged. Viewport adoption, background bake scheduling,
invalidation, image controls, embedded models, exports and broader Qt fixtures
remain required. Full-gate and review results are recorded with the PR before
merge; a passing narrow GPU suite alone is insufficient.
